# 좋은 청자 위대한 청자

초등학교 5학년 사회 「고려청자의 우수성과 다양한 쓰임」 수업을 위한 개별 주문 제작 게임입니다.

## 수업 흐름

53가지 가상 왕실·귀족 주문 중 한 건을 무작위로 받고, 9가지 쓰임 분류에서 형태를 고릅니다. 기존 30개 주문에 도감 예시 23개를 각각 활용한 주문을 추가했습니다. 잔·잔과 받침·연적·조롱박 병도 제작하고, 같은 쓰임 안에서 23개 예시의 세부 형태를 선택할 수 있습니다. 상감·투각·무늬 없는 표현을 선택하고, 장식과 건조→초벌→유약→재벌 과정을 진행합니다. 완성품의 쓰임과 솜씨를 설명하고, 고객 피드백을 보고 다시 만들 수 있습니다.

- 기본 활동: 13분, 주문 한 건 완성 후 서로 다른 쓰임 비교
- 자동 점검: 쓰임 40점, 제작 과정 30점, 주문 특징 10점
- 설명 평가: 쓰임과 모양의 관계 10점, 기법과 효과의 관계 10점. 실제 제작 정보와 이유의 타당성을 평가합니다. 이유가 부족한 문장은 고친 뒤 다시 제출합니다. AI 연결이 불가능하면 기본 기준으로 평가했다는 안내를 표시합니다.
- 속도나 그림 실력, 무작위 결과는 채점하지 않습니다.
- 주전자 몸통의 투각은 이 게임의 단층 모형에서 물이 새므로 주문 특징 점수를 얻지 못합니다. 역사 속 모든 투각 주전자를 일반화한 판정이 아닙니다.

## 저장과 개인정보

학생 이름·로그인·서버 데이터베이스를 사용하지 않습니다. 제작 중인 작품과 완성품 최대 60건은 각 브라우저의 localStorage에 저장합니다. 다른 기기와 자동 공유되지 않으며 브라우저 기록을 삭제하면 지워질 수 있습니다. PNG 작품 카드를 내려받아 교사가 안내한 패들렛 등으로 직접 공유합니다. 글꼴은 자체 포함합니다. 설명 평가를 요청하면 학생이 쓴 두 문장과 작품의 형태·기법·무늬 정보가 `/api/assess`로 전송됩니다. 서버에 문장을 저장하거나 로그로 남기지 않으며, AI 연결 시 Vercel AI Gateway를 통해 평가 모델로 전달됩니다. 이름 등 개인정보는 입력할 필요가 없습니다.

## 실행과 검증

Node.js 20 이상에서 실행합니다. Three.js와 esbuild 버전을 고정해 두었습니다.

```sh
npm ci
npm test
npm run build
npm start
# http://127.0.0.1:4173
```

`dist/`를 정적 호스팅에 게시합니다. Vercel은 `vercel.json`의 buildCommand와 outputDirectory를 사용합니다. 설명 평가에는 `api/assess.js` 서버 함수를 사용합니다. Vercel OIDC 또는 서버의 `AI_GATEWAY_API_KEY`로 인증하며 브라우저에 키를 보내지 않습니다. AI 연결이 없는 로컬 실행과 정적 호스팅은 기본 평가 기준으로 동작합니다.

검증 범위: 무작위 주문과 손님, 단일 활성 주문, 53건 순환 중복 방지, 도감 관찰, 자유로운 흙 성형, 곡면 문양, 앞뒤 벽 투각, 색흙 채우기와 닦기, 네 가마 작업, 네 도자기 선별, 설명 평가와 손님 표정, 작품함·진행 복원·PNG 저장, 네 크롬북 해상도.

## 3D 도감과 한 번에 한 주문

`minichungjamuseum`을 참고한 GLB 23개를 게임 안에서 로딩합니다. 드래그 회전, 확대, 초기 시점 복귀를 지원하며, 닫거나 모델을 바꾸면 이전 로딩과 그래픽 자원을 해제합니다. 스캔 형상, 사진 기반 재현, 참고 청자색의 차이는 각 모델에 표시합니다. 출처와 이용 조건은 `assets/models/README.md`를 확인하세요. 실제 3D 모델은 관찰 도감에만 사용하며 제작 작업대는 2D 일러스트입니다.

진행 중인 주문이 있으면 처음 화면으로 돌아가거나 새로고침해도 그 주문을 이어 합니다. 첫 화면의 새 주문 받기로 새 작업을 시작할 수도 있습니다. 손님은 다섯 명 중 무작위로 정하며 같은 주문을 진행하는 동안 유지됩니다. 각 53건 순환에는 같은 주문이 없고, 순환 경계에서도 최근 두 주문의 즉시 재등장을 피합니다. 주문별 결과물과 명성 점수는 작품 ID 기준으로 갱신되어 재제출해도 같은 작품이 중복 저장되지 않습니다.

앱 소스 진입점은 `app-v3.js`이며 빌드 후 `dist/app.js`가 됩니다. 기존 `app.js`는 1차 버전의 보관 소스입니다.

### 일러스트 제작 작업대

제작 화면은 `craft-2d.js`의 Canvas 2D만 사용합니다. 박물관 GLB의 실루엣을 참고해 새로 그린 23개 무장식 일러스트를 `assets/vessels/`에서 불러옵니다. 원본 유물의 실제 3D는 관찰 도감에서만 사용합니다. 2D 그림을 행별로 변형하고 눌림·흔들림·성형 진행을 보간하는 방식이며 Live2D Cubism SDK나 `.moc3` 모델을 사용하지 않습니다. 선택한 15종은 15도 간격의 24방향 일러스트로 360도 돌려 봅니다. 좌우 드래그, 방향키와 회전 화살표를 지원합니다. X 표시로 제외한 8종의 기존 그림과 도감 자료는 보존하고, 새 형태를 고를 때는 회전 가능한 예시를 우선합니다.

처음에는 구멍 없는 흙덩어리로 시작하고 흙의 점을 자유롭게 늘리고 눌러 목표 윤곽을 맞춥니다. 실제 윤곽이 90% 이상 일치하면 완성 형태가 나타납니다. 뒤로 돌아가면 그 단계와 이후 제작 과정을 초기화합니다. 의자와 베개, 향로 뚜껑에 원본 유물의 기존 투각을 미리 넣지 않습니다. 투각은 앞벽과 뒷벽을 별도로 처리합니다. 앞쪽 구멍에는 어두운 내부와 막힌 반대편 벽이 보이고, 반대쪽을 회전해 직접 뚫었을 때만 그 벽에도 구멍이 생깁니다. 양쪽의 구멍이 시선상 겹칠 때만 작업대가 보입니다. 가장자리에 흙의 두께를 표현하고 되돌리기와 기법 변경을 지원합니다. 상감은 파기 → 백토·자토 채우기 → 걷어내기 단계로 표현합니다. 손그림 색상은 건조·초벌·유약 단계에 따라 달라집니다.

표면 좌표는 높이와 둘레 각도로 저장하며, 회전 방향에 따라 문양의 가로 위치·폭과 앞뒤 가림을 계산합니다. 주둥이·동물 장식을 포함한 복잡한 형상의 표면 투영은 학습용 근사이며 CAD나 물리 시뮬레이션은 아닙니다. 기존 3D 작품의 좌표가 있는 진행 중 작품은 근사 위치로 옮기며, 작품함의 기존 사진은 그대로 보존합니다. `drawing.js`는 외부 AI 없이 학·구름·연꽃 템플릿과 선 모양을 비교하는 제한적인 후보 제안입니다. 확신이 낮으면 단정하지 않고, 학생이 그림의 뜻을 정합니다.

### 예시에서 주문으로

`example-orders.js`는 도감의 23개 예시를 제작 분류·세부 모델·주문·문양 조건에 연결합니다. 추가 모델은 PR #1의 GLB와 출처 기록을 그대로 사용합니다. 오리 연적/오리 향로, 조롱박 주전자/조롱박 병처럼 닮은 모양과 다른 쓰임을 비교할 수 있습니다. 새 주문은 모란·국화·매화·대나무·버드나무·포도·풀꽃·글자를 포함하며, 복합 무늬 주문은 각 무늬를 모두 확인합니다. 그리기 인식 후보는 여전히 학·구름·연꽃으로 한정하고, 다른 문양은 학생이 뜻을 정할 수 있습니다.

주문서에 세부 형태·기법·필요 무늬를 표시하고 참고 예시를 바로 열 수 있습니다. 도감을 본 것만으로 제작 형태가 자동 선택되지는 않습니다. 새 주문의 특징 10점은 세부 모델·모든 무늬·기법·쓰임에 맞는 장식을 함께 확인합니다. 기존 주문 ID와 저장 형식은 유지하며, 옛 작품의 `modelId`가 없으면 기본 형태를 사용합니다. 무작위 주문은 전체 순환 내 중복을 막고, 가능한 경우 직전과 다른 쓰임을 우선합니다.

원본의 장식 기법과 학습자가 새로 꾸미는 기법은 다를 수 있습니다. 모란 주전자의 역상감·풀꽃 주전자의 퇴화·시문 병의 새김 등 원본 정보는 도감에 남기고, 게임의 새 문양은 지원하는 상감·투각·무문 표현으로 단순화합니다. 시기 미정 기린 향로를 고려시대 진품으로 단정하지 않습니다.

### 한 화면 아케이드 작업대

빌드 진입점은 `app-v3.js`입니다. `arcade.css`는 크롬북의 1366×768·1280×720·1024×600·1536×864 화면을 기준으로 작업대와 도구를 한 화면에 배치합니다. 기본 게임에 페이지 스크롤이 없으며 상세 주문, 학습 자료, 작품 소개는 별도 대화상자에서 엽니다. 휴대폰 전용 화면은 만들지 않습니다.

- `sculpt-game.js`: 선택한 일러스트의 윤곽을 목표로 제시하고, 흙을 누른 채 끌어 늘려 모양을 맞춥니다. 목표 모양에 90% 이상 맞으면 밝은 통과 효과를 보여 줍니다. 방향키와 스페이스바 조작도 지원합니다. 이미 만든 옛 작품은 강제로 다시 빚게 하지 않습니다.
- `craft-2d.js` / `motif-paths.js`: 새 문양의 투각은 Canvas의 `destination-out`으로 그림 자체를 뚫습니다. `openwork.js` / `craft-3d.js`는 이전 3D 제작 버전의 보관 소스이며 현재 제작 화면에서 불러오지 않습니다.
- `kiln-game.js` / `arcade-rules.js`: 부채를 움직여 건조하고 붓으로 직접 유약을 칠하며, 초벌·재벌에서는 온도를 유지하는 미니게임입니다. 스페이스바를 누르면 온도가 오르고 떼면 내려갑니다. 초록 구간에 머문 시간을 모아 완료하며 과열·과냉각은 재도전합니다. 일시정지·화면 전환 시 누르기 상태가 풀립니다. 게임의 온도 게이지·시간은 학습용 단순화이며 실제 온도 수치나 제작 시간을 뜻하지 않습니다. 미니게임 실수나 속도는 학습 점수에 영향을 주지 않습니다.
- `characters.js` / `assets/characters/`: 이미지 생성으로 만든 다섯 손님의 앞·뒤·양옆 시트와 손님별 기쁨·미묘함·화남 반신상 15종을 사용합니다. 사용자 제공 고려 복식과 공방 배경을 참고한 창작 일러스트입니다. 게임에는 주문하는 손님만 표시합니다. 제작자용 원본 4방향 시트는 `assets/characters/source/`에 보관하며, 게임의 캐릭터 도감·시트 다운로드 메뉴는 제공하지 않습니다.

주문은 카운터의 손님 대화로 받고, 흙 준비 → 성형 → 장식 → 가마 → 선별 → 카운터 전달로 화면을 전환합니다. `stations.css`와 새 `assets/scenes/`의 평면 일러스트가 작업별 큰 작업 공간과 상단 재료 트레이를 구성합니다. 캐릭터도 같은 차분한 파스텔·갈색 윤곽선 화풍으로 다시 제작했습니다.

- `clay.js` / `clay-workshop.css`: 몸통용 태토를 자동으로 준비하고 여섯 번 반죽합니다. 상감용 백토·자토는 별도의 색흙 채우기 단계에서 고릅니다. 흙의 접지점을 배경 속 회전판에 맞추고 누르기·드래그·스페이스바에 따라 눌림과 늘어남을 표시합니다. 반죽 완료 뒤에도 흙은 조작에 반응합니다. 선택한 색흙을 상감 표현에 반영합니다.
- `inspection.js`: 재벌 뒤 네 점을 나란히 놓고 금·뒤틀림·유약 불균일이 있는 세 점을 망치로 깨뜨려 정상 한 점을 남깁니다. 정상 작품을 깨뜨리면 실패 효과와 다시 고르기를 표시합니다.

회전 원화와 PNG 추출 정보는 `assets/vessels/rotations/manifest.json`, 레이아웃 기준은 `layouts.json`에 기록합니다. 원화 시트와 게임용 프레임의 해시를 보존하며 24장 모두 같은 바닥 높이로 맞춥니다. 작품함에서는 완성품을 다시 돌려 보고 현재 방향을 PNG로 저장할 수 있습니다. 공방은 사진의 실제 도예 작업대 배치를 참고한 회전판·색흙 그릇·붓·조각칼 구성으로 다시 그렸습니다. Jua 글꼴은 OFL 라이선스와 함께 자체 포함하여 외부 폰트 서버에 의존하지 않습니다.

### 브라우저 회귀 검사

`npm run build` 후 `npm start`를 실행하고 별도 터미널에서 `npm run test:browser`를 실행합니다. 처음에는 `npx playwright install chromium`이 필요합니다. 다른 서버는 `BASE_URL`, 설치된 Chromium은 `CHROMIUM_PATH`로 지정할 수 있습니다. 검사는 격리된 브라우저 프로필에서 주문·반죽·성형·앞뒤 투각·그리기 인식·가마·선별·납품·작품함 복원과 360장 회전 및 네 크롬북 해상도를 확인합니다. 실제 사용자의 저장 데이터를 읽거나 바꾸지 않습니다.

첫 화면은 새 방문자에게 **새 주문 받기**만 보여 줍니다. 진행 중인 유효한 작업이 저장돼 있으면 같은 크기의 **공방 일 이어하기**를 나란히 표시합니다. 새 주문은 작업 초안을 새로 만들고 기존 주문 이력과 작품함은 보존합니다. `npm run test:entry`로 첫 방문·이어하기·새 주문·잘못된 저장 상태와 네 크롬북 해상도를 검사합니다.

`npm run test:shaping`은 흙을 실제로 당기는 동작, 위쪽 윤곽 도달, 90% 통과, 진행률 복원과 키보드 조작을 검증합니다.

`test:decoration`, `test:kiln`, `test:inspection`, `test:assessment`, `test:ui`는 각 작업의 포인터·키보드 조작, 순서, 화면 배치와 설명 제출을 검사합니다. `assessment.test.js`는 실제 외부 모델 호출 없이 응답 검증·기본 기준·서버 오류 처리를 검사하며, 실제 AI 연결 여부는 배포 환경에서 별도로 확인해야 합니다.
