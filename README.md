# 좋은 청자 위대한 청자

초등학교 5학년 사회 「고려청자의 우수성과 다양한 쓰임 알아보기」 수업을 위한 교사·학생 활동 화면과 개별 주문 제작 게임입니다.

기본 주소 `/`는 학생 참여 화면 `/lesson`으로 이동합니다. 교사 화면은 `/teacher`, 학생 화면은 `/lesson`, 공개수업 참관 화면은 `/observe`입니다. 3D 비교, 이름·쓰임 예상, 청자 제작 게임을 교사가 순서대로 진행합니다. 수업 참여 방법, 자료 출처, 서버 저장과 개인정보 처리는 [CLASSROOM.md](CLASSROOM.md)를 확인하세요. 아래의 기존 게임 저장 설명은 독립 게임(`/game`)에 해당합니다.

## 수업 흐름

53가지 가상 왕실·귀족 주문 중 한 건을 무작위로 받고, 9가지 쓰임 분류에서 형태를 고릅니다. 기존 30개 주문에 도감 예시 23개를 각각 활용한 주문을 추가했습니다. 잔·잔과 받침·연적·조롱박 병도 제작하고, 같은 쓰임 안에서 23개 예시의 세부 형태를 선택할 수 있습니다. 상감·투각·무늬 없는 표현을 선택하고, 장식과 건조→초벌→유약→재벌 과정을 진행합니다. 완성품의 쓰임과 솜씨를 설명하고, 고객 피드백을 보고 다시 만들 수 있습니다.

- 기본 활동: 13분, 주문 한 건 완성 후 서로 다른 쓰임 비교
- 자동 점검: 쓰임 40점, 제작 과정 30점, 주문 특징 10점
- 설명 평가: 모양·문양·쓰임 소개 10점, 공들인 부분·기법 소개 10점. 모양과 특징을 짧게 소개하고 특정 부분에 들인 노력이나 사용한 기법을 적으면 통과합니다. 자세한 과정과 이유는 추가 점수에 반영하며 필수 문장 형식을 요구하지 않습니다. 빈칸·무관한 글·실제 기법과 명백히 모순되는 설명은 고친 뒤 다시 제출합니다. AI 연결이 불가능해도 같은 통과 기준의 기본 평가로 진행합니다.
- 속도나 그림 실력, 무작위 결과는 채점하지 않습니다.
- 주전자 몸통의 투각은 이 게임의 단층 모형에서 물이 새므로 주문 특징 점수를 얻지 못합니다. 역사 속 모든 투각 주전자를 일반화한 판정이 아닙니다.

## 저장과 개인정보

학생 이름·로그인·서버 데이터베이스를 사용하지 않습니다. 제작 중인 작품과 완성품 최대 60건은 각 브라우저의 localStorage에 저장합니다. 다른 기기와 자동 공유되지 않으며 브라우저 기록을 삭제하면 지워질 수 있습니다. PNG 작품 카드를 내려받아 교사가 안내한 패들렛 등으로 직접 공유합니다. 글꼴은 자체 포함합니다. 설명 평가를 요청하면 학생이 쓴 두 문장과 작품의 형태·기법·무늬 정보가 `/api/assess`로 전송됩니다. 앱 서버에 문장을 저장하거나 로그로 남기지 않습니다. `OPENAI_API_KEY`가 있으면 서버에서 OpenAI로 직접 전송하고, 없으면 기존 Vercel AI Gateway를 사용합니다. 직접 요청에는 `store: false`를 지정하며 제공자의 별도 데이터 처리 정책은 적용됩니다. API 키는 서버에서만 읽고 브라우저로 보내지 않습니다. 이름 등 개인정보는 입력할 필요가 없습니다.

## 실행과 검증

Node.js 20 이상에서 실행합니다. Three.js와 esbuild 버전을 고정해 두었습니다.

```sh
npm ci
npm test
npm run build
npm start
# http://127.0.0.1:4173
```

`dist/`를 정적 호스팅에 게시합니다. Vercel은 `vercel.json`의 buildCommand와 outputDirectory를 사용합니다. 설명 평가에는 `api/assess.js` 서버 함수를 사용합니다. AI 연결이 없는 로컬 실행과 정적 호스팅은 기본 평가 기준으로 동작합니다.

### OpenAI 키 연결

1. [프로젝트 환경 변수](https://vercel.com/baeppy/celadon-tycoon/settings/environment-variables)에서 이름을 `OPENAI_API_KEY`, 값을 OpenAI에서 발급한 키로 등록합니다. 유형은 **Secret**, 환경은 **Production**을 선택합니다. 미리보기에서도 AI를 시험하려면 Preview에 별도 테스트용 키를 등록합니다.
2. 저장 후 새 배포를 실행합니다. 기존 배포에는 나중에 추가한 환경 변수가 적용되지 않습니다. 키를 채팅·소스 코드·`VITE_` 또는 `NEXT_PUBLIC_` 변수에 넣지 않습니다.
3. 설명을 제출해 결과의 `source: "ai"`와 서버 로그를 확인합니다. GET `/api/assess`의 `aiConfigured`와 `provider`는 설정 유무만 나타내며, `check: "authentication-only"`는 실제 모델 호출을 시험하지 않았다는 뜻입니다.

OpenAI 키가 설정되면 `https://api.openai.com/v1/chat/completions`만 호출합니다. Vercel AI Gateway 크레딧은 필요하지 않으며 모델 사용료는 OpenAI 계정에 청구됩니다. 기본 모델은 [공식 문서에서 구조화된 출력 지원을 확인한 `gpt-5.4-mini`](https://developers.openai.com/api/docs/models/gpt-5.4-mini)입니다. 필요하면 서버 환경 변수 `OPENAI_MODEL`에 OpenAI 모델 ID를 지정합니다. Gateway용 `openai/` 접두사는 붙이지 않습니다. 응답을 2,000 토큰으로 제한하고 오류나 시간 초과 시 추가 유료 호출 없이 기본 평가로 전환합니다.

워드 클라우드의 **비슷한 답 묶기**(`api/cloud-groups.js`)도 같은 설정을 씁니다. 워드 클라우드를 띄운 선생님 화면이나 PPT용 주소 화면이 새 답이 있을 때만, 한 워드 클라우드에 5~7초에 한 번까지 부탁하며, 이름 없이 서로 다른 답(최대 80개)과 답마다 몇 명이 썼는지만 보냅니다. 응답은 3,000 토큰으로 제한하고, 오류나 시간 초과(15초) 때는 규칙으로 합친 낱말을 그대로 보여 줍니다. 로컬 서버에서 AI 없이 화면을 확인할 때는 `CLASSROOM_FAKE_GROUPING=1 node server.mjs`로 정해진 묶음(머리·베고·낮잠·누워가 든 답을 한 낱말로)을 흉내 냅니다.

OpenAI 키가 없을 때만 기존 Gateway의 `AI_GATEWAY_API_KEY` 또는 Vercel OIDC 인증을 사용합니다. OpenAI 키와 Gateway 키는 서로 바꿔 넣을 수 없습니다. 로컬 Node 서버는 `.env.local`을 자동으로 읽지 않으므로 필요할 때 `node --env-file=.env.local server.mjs`로 실행합니다. 이 파일은 Git에서 제외됩니다.

검증 범위: 무작위 주문과 손님, 단일 활성 주문, 53건 순환 중복 방지, 도감 관찰, 자유로운 흙 성형, 곡면 문양, 앞뒤 벽 투각, 색흙 채우기와 닦기, 네 가마 작업, 네 도자기 선별, 설명 평가와 손님 표정, 작품함·진행 복원·PNG 저장, 네 크롬북 해상도.

## 3D 도감과 한 번에 한 주문

`minichungjamuseum`을 참고한 GLB 23개를 게임 안에서 로딩합니다. 드래그 회전, 확대, 초기 시점 복귀를 지원하며, 닫거나 모델을 바꾸면 이전 로딩과 그래픽 자원을 해제합니다. 스캔 형상, 사진 기반 재현, 참고 청자색의 차이는 각 모델에 표시합니다. 출처와 이용 조건은 `assets/models/README.md`를 확인하세요. 실제 3D 모델은 관찰 도감에만 사용하며 제작 작업대는 2D 일러스트입니다.

진행 중인 주문이 있으면 처음 화면으로 돌아가거나 새로고침해도 그 주문을 이어 합니다. 첫 화면의 새 주문 받기로 새 작업을 시작할 수도 있습니다. 손님은 다섯 명 중 무작위로 정하며 같은 주문을 진행하는 동안 유지됩니다. 각 53건 순환에는 같은 주문이 없고, 순환 경계에서도 최근 두 주문의 즉시 재등장을 피합니다. 주문별 결과물과 명성 점수는 작품 ID 기준으로 갱신되어 재제출해도 같은 작품이 중복 저장되지 않습니다.

앱 소스 진입점은 `app-v3.js`이며 빌드 후 `dist/app.js`가 됩니다. 기존 `app.js`는 1차 버전의 보관 소스입니다.

### 일러스트 제작 작업대

제작 화면은 `craft-2d.js`의 Canvas 2D만 사용합니다. 박물관 GLB의 실루엣을 참고해 새로 그린 23개 무장식 일러스트를 `assets/vessels/`에서 불러옵니다. 원본 유물의 실제 3D는 관찰 도감에서만 사용합니다. 2D 그림을 행별로 변형하고 눌림·흔들림·성형 진행을 보간하는 방식이며 Live2D Cubism SDK나 `.moc3` 모델을 사용하지 않습니다. 선택한 15종은 15도 간격의 24방향 일러스트로 360도 돌려 봅니다. 좌우 드래그, 방향키와 회전 화살표를 지원합니다. X 표시로 제외한 8종의 기존 그림과 도감 자료는 보존하고, 새 형태를 고를 때는 회전 가능한 예시를 우선합니다.

처음에는 구멍 없는 흙덩어리로 시작하고 흙의 점을 자유롭게 늘리고 눌러 목표 윤곽을 맞춥니다. 실제 윤곽이 90% 이상 일치하면 완성 형태가 나타납니다. 뒤로 돌아가면 그 단계와 이후 제작 과정을 초기화합니다. 의자와 베개, 향로 뚜껑에 원본 유물의 기존 투각을 미리 넣지 않습니다. 투각은 앞벽과 뒷벽을 별도로 처리합니다. 앞쪽 구멍에는 어두운 내부와 막힌 반대편 벽이 보이고, 반대쪽을 회전해 직접 뚫었을 때만 그 벽에도 구멍이 생깁니다. 양쪽의 구멍이 시선상 겹칠 때만 작업대가 보입니다. 가장자리에 흙의 두께를 표현하고 되돌리기와 기법 변경을 지원합니다. 상감은 파기 → 백토·자토 채우기 → 걷어내기 단계로 표현합니다. 손그림 색상은 건조·초벌·유약 단계에 따라 달라집니다.

표면 좌표는 높이와 둘레 각도로 저장하며, 회전 방향에 따라 문양의 가로 위치·폭과 앞뒤 가림을 계산합니다. 주둥이·동물 장식을 포함한 복잡한 형상의 표면 투영은 학습용 근사이며 CAD나 물리 시뮬레이션은 아닙니다. 기존 3D 작품의 좌표가 있는 진행 중 작품은 근사 위치로 옮기며, 작품함의 기존 사진은 그대로 보존합니다. `drawing.js`는 외부 AI 없이 학·구름·연꽃 템플릿과 선 모양을 비교하는 제한적인 후보 제안입니다. 확신이 낮으면 단정하지 않고, 학생이 그림의 뜻을 정합니다.

무늬 넣는 작업대의 **크게 보기**를 누르면 위쪽 무늬·기법 선반을 잠시 접고 도자기를 작업 공간 가득 키웁니다(1366×768에서 약 1.4~1.6배, 1024×600에서 약 1.4~1.7배). 찍기·그리기·돌려보기·지우기와 무늬 크기 조절은 그대로 쓰고, 무늬나 기법을 바꿀 때는 **작게 보기**로 돌아갑니다. 확대는 보는 방법일 뿐이라 작품 자료에는 저장하지 않으며, 색흙 채우기·닦아내기까지 이어지고 가마 작업대에서는 원래 크기로 돌아갑니다. 휴대폰 배치에서는 이미 화면 폭을 다 쓰므로 버튼을 숨깁니다.

상감의 색흙 채우기에서는 **흰 흙(백토)과 붉은 흙(자토)을 한 작품에 함께** 쓸 수 있습니다. **자토는 붉은 흙이지만 구우면 검은 무늬가 됩니다.** 게임에서도 붓과 도자기 위에서는 붉게 보이고(`craft-2d.js`의 `inlayColor`), 유약을 바르고 구운 뒤(완성작·작품함·수업 화면)에는 검은색으로 나옵니다. 흰 흙은 처음부터 끝까지 흰색입니다. 붓에 묻힌 흙으로 문지른 자리만 그 흙이 되고, 다른 흙으로 다시 문지르면 그 자리가 바뀝니다(다 채운 뒤에도 닦아내기 전까지 가능). 흙의 종류는 무늬 칸마다 `inlay.dark`(자토 칸 목록, 자료 안의 이름은 예전 그대로 `dark`)에 저장하고, 작품 요약 `clay.slip`은 `white`·`dark`·`mixed` 가운데 하나입니다. 90%를 채워 자동 완성될 때 붓이 닿지 않은 칸은 가장 가까운 칸의 색을 따릅니다. `inlay.dark`가 없는 예전 작품은 전처럼 한 가지 색으로 그립니다. **색흙 다시 채우기**(오른쪽 도구 자리)는 판 무늬는 그대로 두고 채운 색흙만 모두 걷어 내 처음부터 다시 채우게 합니다. 채점 도움말과 AI 확인에는 두 색을 함께 썼다는 사실이 전달됩니다.

**무늬는 두 가지 이상, 네 개 이상.** 상감·투각으로 꾸미는 작품은 무늬 작업대에서 **두 가지 이상의 무늬를 모두 4개 이상** 넣어야 다음 순서(색흙 채우기·구멍 다듬기)로 넘어갑니다(`domain.js`의 `MIN_MOTIFS`, `MIN_MOTIF_KINDS`, `decorationProgress`). 도장 하나가 무늬 하나이고, 직접 그린 그림은 선이 몇 개든 ‘그림의 뜻’으로 고른 무늬 하나로 셉니다(뜻을 고르지 않으면 따로 한 가지). 작업대 왼쪽에 **무늬 3/4개 · 종류 1/2가지**처럼 지금 개수가 보이고, 채우면 초록 ✓로 바뀌며 아래 버튼이 열립니다. 무문(무늬 없이 표현하기)은 무늬가 필요 없습니다.

**무늬 주문은 두 가지 무늬를 말하되, 몇 개씩 넣을지는 정하지 않습니다.** 무늬를 정해 주는 주문 38건은 “무늬는 학에 구름을 곁들여 주시오.”처럼 두 가지(한 건은 세 가지) 무늬를 주문합니다(`domain.js`의 `ORDER_MOTIFS`, `orderMotifs`, `motifRequest`). 개수는 만드는 사람이 정합니다. 손님의 말(`dialogue.js`의 `orderQuote`)과 ‘오늘의 주문’ 요약(무늬: 학 · 구름)에 그대로 나옵니다. 무늬를 맡기는 주문 7건은 “무늬를 넣는다면 두 가지를 섞어 넣어 주시오.”(투각 주문은 “구멍무늬는 두 가지 모양을 섞어 뚫어 주시오.”)라고 덧붙입니다. 채점의 ‘주문의 세부 형태·기법·무늬’(10점)는 주문한 무늬가 **종류마다 하나 이상** 들어갔는지 봅니다(더 넣거나 다른 무늬를 곁들이는 것은 괜찮음). 직접 그려 뜻을 붙인 무늬도 그 종류로 칩니다. 빠진 무늬가 있으면 “주문에 있는 학·구름를 다시 확인해 보세요. 주문한 무늬가 모두 들어갔는지 견주어 보세요.”라고 알려 줍니다.

### 글꼴

사이트 전체가 선생님이 고른 두 글꼴을 씁니다. 보통 글씨는 **학교안심 보드마카 R**, 굵은 글씨(제목·버튼·워드 클라우드 낱말)는 **빗썸고딕 Original**이며, 하나의 글꼴 이름 `Celadon Text`로 묶어 선언합니다(`classroom.css`, `present.html`, `ppt-addin/index.html`, `ppt-addin/legacy.css`). 게임은 Jua 자리에 학교안심 보드마카 R만 씁니다(`Celadon Game`, `stations.css`). 파일과 라이선스 안내는 `assets/fonts/README.md`에 있습니다. 빗썸고딕에 없는 한글(2,350자 밖)과 기호는 다음 글꼴로 넘어갑니다.

### 예시에서 주문으로

`example-orders.js`는 도감의 23개 예시를 제작 분류·세부 모델·주문·문양 조건에 연결합니다. 추가 모델은 PR #1의 GLB와 출처 기록을 그대로 사용합니다. 오리 연적/오리 향로, 조롱박 주전자/조롱박 병처럼 닮은 모양과 다른 쓰임을 비교할 수 있습니다. 새 주문은 모란·국화·매화·대나무·버드나무·포도·풀꽃·글자를 포함하며, 복합 무늬 주문은 각 무늬를 모두 확인합니다. 그리기 인식 후보는 여전히 학·구름·연꽃으로 한정하고, 다른 문양은 학생이 뜻을 정할 수 있습니다.

주문서에 세부 형태·기법·필요 무늬를 표시하고 참고 예시를 바로 열 수 있습니다. 도감을 본 것만으로 제작 형태가 자동 선택되지는 않습니다. 새 주문의 특징 10점은 세부 모델·모든 무늬·기법·쓰임에 맞는 장식을 함께 확인합니다. 기존 주문 ID와 저장 형식은 유지하며, 옛 작품의 `modelId`가 없으면 기본 형태를 사용합니다. 무작위 주문은 전체 순환 내 중복을 막고, 가능한 경우 직전과 다른 쓰임을 우선합니다.

원본의 장식 기법과 학습자가 새로 꾸미는 기법은 다를 수 있습니다. 모란 주전자의 역상감·풀꽃 주전자의 퇴화·시문 병의 새김 등 원본 정보는 도감에 남기고, 게임의 새 문양은 지원하는 상감·투각·무문 표현으로 단순화합니다. 시기 미정 기린 향로를 고려시대 진품으로 단정하지 않습니다.

### 한 화면 아케이드 작업대

빌드 진입점은 `app-v3.js`입니다. `arcade.css`는 크롬북의 1366×768·1280×720·1024×600·1536×864 화면을 기준으로 작업대와 도구를 한 화면에 배치합니다. 기본 게임에 페이지 스크롤이 없으며 상세 주문, 학습 자료, 작품 소개는 별도 대화상자에서 엽니다. 휴대폰 전용 화면은 만들지 않습니다.

- `sculpt-game.js`: 선택한 일러스트의 윤곽을 목표로 제시하고, 흙을 누른 채 끌어 늘려 모양을 맞춥니다. 목표 모양에 90% 이상 맞으면 밝은 통과 효과를 보여 줍니다. **무늬 작업대로 →**를 누르면 모든 학생에게 같은 질문 창이 열립니다. 손님의 주문을 다시 보여 주고 “이 모양이 손님이 말한 쓰임에 맞나요?”를 묻습니다. 모양이 맞는지 틀리는지는 알려 주지 않으며(쓰임 40점 평가는 그대로), **모양 다시 고를래요**를 누르면 모양 작업대에 남아 다른 모양을 고를 수 있습니다. 방향키와 스페이스바 조작도 지원합니다. 이미 만든 옛 작품은 강제로 다시 빚게 하지 않습니다.
- `craft-2d.js` / `motif-paths.js`: 새 문양의 투각은 Canvas의 `destination-out`으로 그림 자체를 뚫습니다. `openwork.js` / `craft-3d.js`는 이전 3D 제작 버전의 보관 소스이며 현재 제작 화면에서 불러오지 않습니다.
- `kiln-game.js` / `arcade-rules.js`: 부채를 움직여 건조하고 붓으로 직접 유약을 칠하며, 초벌·재벌에서는 온도를 유지하는 미니게임입니다. 스페이스바를 누르면 온도가 오르고 떼면 내려갑니다. 초록 구간에 머문 시간을 모아 완료하며 과열·과냉각은 재도전합니다. 일시정지·화면 전환 시 누르기 상태가 풀립니다. 게임의 온도 게이지·시간은 학습용 단순화이며 실제 온도 수치나 제작 시간을 뜻하지 않습니다. 미니게임 실수나 속도는 학습 점수에 영향을 주지 않습니다.
- `characters.js` / `assets/characters/`: 이미지 생성으로 만든 다섯 손님의 앞·뒤·양옆 시트와 손님별 기쁨·미묘함·화남 반신상 15종을 사용합니다. 사용자 제공 고려 복식과 공방 배경을 참고한 창작 일러스트입니다. 게임에는 주문하는 손님만 표시합니다. 제작자용 원본 4방향 시트는 `assets/characters/source/`에 보관하며, 게임의 캐릭터 도감·시트 다운로드 메뉴는 제공하지 않습니다.

주문은 카운터의 손님 대화로 받고, 흙 준비 → 성형 → 장식 → 가마 → 선별 → 카운터 전달로 화면을 전환합니다. `stations.css`와 새 `assets/scenes/`의 평면 일러스트가 작업별 큰 작업 공간과 상단 재료 트레이를 구성합니다. 캐릭터도 같은 차분한 파스텔·갈색 윤곽선 화풍으로 다시 제작했습니다.

- `clay.js` / `clay-workshop.css`: 몸통용 태토를 자동으로 준비하고 여섯 번 반죽합니다. 상감용 백토·자토는 별도의 색흙 채우기 단계에서 고릅니다. 흙의 접지점을 배경 속 회전판에 맞추고 누르기·드래그·스페이스바에 따라 눌림과 늘어남을 표시합니다. 반죽 완료 뒤에도 흙은 조작에 반응합니다. 선택한 색흙을 상감 표현에 반영합니다.
- `inspection.js`: 재벌 뒤 네 점을 나란히 놓고 금·뒤틀림·유약 불균일이 있는 세 점을 망치로 깨뜨려 정상 한 점을 남깁니다. 정상 작품을 깨뜨리면 실패 효과와 다시 고르기를 표시합니다.

회전 원화와 PNG 추출 정보는 `assets/vessels/rotations/manifest.json`, 레이아웃 기준은 `layouts.json`에 기록합니다. 원화 시트와 게임용 프레임의 해시를 보존하며 24장 모두 같은 바닥 높이로 맞춥니다. 작품함에서는 완성품을 다시 돌려 보고 현재 방향을 PNG로 저장할 수 있습니다. 공방은 사진의 실제 도예 작업대 배치를 참고한 회전판·색흙 그릇·붓·조각칼 구성으로 다시 그렸습니다. Jua 글꼴은 OFL 라이선스와 함께 자체 포함하여 외부 폰트 서버에 의존하지 않습니다.

### 브라우저 회귀 검사

`npm run build` 후 `npm start`를 실행하고 별도 터미널에서 `npm run test:browser`를 실행합니다. 처음에는 `npx playwright install chromium`이 필요합니다. 다른 서버는 `BASE_URL`, 설치된 Chromium은 `CHROMIUM_PATH`로 지정할 수 있습니다. 검사는 격리된 브라우저 프로필에서 주문·반죽·성형·앞뒤 투각·그리기 인식·가마·선별·납품·작품함 복원과 360장 회전 및 네 크롬북 해상도를 확인합니다. 실제 사용자의 저장 데이터를 읽거나 바꾸지 않습니다.

첫 화면은 새 방문자에게 **새 주문 받기**만 보여 줍니다. 진행 중인 유효한 작업이 저장돼 있으면 같은 크기의 **공방 일 이어하기**를 나란히 표시합니다. 새 주문은 작업 초안을 새로 만들고 기존 주문 이력과 작품함은 보존합니다. 이어할 작업이 있을 때 새 주문 받기를 누르면 진행 중인 작업을 포기할지 먼저 묻습니다. `npm run test:entry`로 첫 방문·이어하기·새 주문·잘못된 저장 상태와 네 크롬북 해상도를 검사합니다.

`npm run test:shaping`은 흙을 실제로 당기는 동작, 위쪽 윤곽 도달, 90% 통과, 진행률 복원과 키보드 조작을 검증합니다.

`test:decoration`, `test:kiln`, `test:inspection`, `test:assessment`, `test:ui`는 각 작업의 포인터·키보드 조작, 순서, 화면 배치와 설명 제출을 검사합니다. `test:decor-tools`는 크게 보기(1024×600·1366×768에서 도구가 가려지지 않는지), 확대한 채 무늬 찍기, 흰 색흙과 검은 색흙 함께 쓰기, 다른 색으로 다시 칠하기, 색흙 다시 채우기와 닦아낸 뒤 두 색이 남는지를 검사합니다. `assessment.test.js`는 실제 외부 모델 호출 없이 응답 검증·기본 기준·서버 오류 처리를 검사하며, 실제 AI 연결 여부는 배포 환경에서 별도로 확인해야 합니다.

주문 요약은 자체 생성한 밝은 한지 배경에 표시합니다. 카운터 왼쪽에는 벼루·연적·붓, 오른쪽에는 실제 은 궁서체 제목을 얹은 청자 도감 책을 놓습니다. 책은 주문·전달·평가 화면에서 도감을 여는 버튼입니다. 문양 10종은 박물관 청자 자료를 참고해 다시 그렸고, 국화 문양은 유지했습니다. 그림 원본과 글꼴 라이선스를 각 assets 디렉터리에 보존합니다.

`test:dialogue`는 가장 긴 주문 두 개와 다섯 손님을 두 크롬북 해상도에서 확인합니다. 말풍선의 왼쪽 꼬리, 큰 글씨와 답변 버튼의 잘림을 검사합니다. 제작이 만점이고 설명만 부족할 때는 작품을 잘 만들었다고 인정한 뒤 설명 보완을 요청합니다.
